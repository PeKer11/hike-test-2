Round 1 Design Specification (6 Summary Points)

  • 1. Role Tokens, 5-Size Type Scale, Radii & Shadows: Day tokens: --bg: #fbf8f4, --surface: #fcf7f0, --surface-strong: #ffffff, --ink: #1e3d2f, --ink-body: #231f1c, --muted: #586656 (darkened from #5f6f5d to pass ≥ 4.8:1 AA on cream), --line: #e2d8c9, --primary: #c15f3c, --route: #25604b, --danger: #b43228. Night swaps in one [data-theme="night"] block: --bg: #181614, --surface: #221f1c, --ink: #f4efe8, --muted: #b0a79b, --line: #38322c, keeping --primary: #c15f3c and lifting route green to #4ca382. Fonts kept: Secular One (expressive Hebrew+Latin display) + Heebo (clean geometric Hebrew+Latin UI). Strict 5-step scale: 26px, 20px, 16px, 14px, 13px. Radii: 6px / 8px / 10px; shadows restricted to 1px structural hairlines plus subtle sheet lift (0 -2px 12px rgba(35,31,28,.08)).
  • 2. What Was Removed: Eliminated the muddy full-screen blurred photo backgrounds; the raw Latitude / Longitude, Search radius (km), and Max distance inputs from the primary Plan view; competing dual forms ("Name your own stops" vs "City Walk Companion"); nested cards-in-cards; the oversized floating circular + FAB in the navigation bar; 3D clipart breaking card borders; border-only active pills; and the giant standalone white copyright card in Me.
  • 3. Hero Element of Each Screen: (A) Home: Instant duration selector + Plan a walk button anchored beneath a calm Jerusalem hills wash. (B) Plan + Assistant: Ori (custom 3-stone trail cairn mark) inside a calm atmospheric landscape header leading directly into a single conversational request + duration bar. (C) Live Walk: Crisp bottom sheet (phone) / floating dock (desktop) spotlighting the numbered next stop and Mark stop reached verb over the live route line. (D) My Walks: High-density 1px hairline route list (and a 1-line + 1-button teaching empty state). (E) Me: Unified preference table with instant solid-fill EN/עב and Day/Night switches. (F) Login: Single passwordless email-code input with inline plain-word error validation.
  • 4. First-Class RTL (Hebrew) Decisions: Built 100% with CSS logical properties (padding-inline, border-inline-end, inset-inline-start, text-align: start). Switching to dir="rtl" moves the desktop navigation rail and the Live Walk floating sheet to the right (start) side, aligns all labels/inputs/punctuation naturally right-to-left (fixing the broken leading period seen in the current screenshot’s .have — we'll build), and mirrors directional arrows/chevrons via .flip-rtl while keeping map geography and numbers un-flipped.
  • 5. Phone vs. Desktop Ergonomics: On Phone, Plan places Ori and the request input first so the user immediately knows what to do without scrolling past a half-screen map; navigation sits in a 5-slot thumb bar. On Desktop, navigation becomes a 200px inline-start rail with the Traike wordmark, Plan splits into a 430px conversational drawer beside a full-height map, and Live Walk docks its guidance card top-start over the map.
  • 6. Honest Critique — What Is Still Weak for Round 2: (a) On short phones (< 680px height) when the virtual keyboard opens on Plan, the atmospheric hero band + Ori bubble could push the Build walking route button below the keyboard—in React we should collapse the hero band on input focus. (b) Multi-turn chat history (when a user asks 3–4 follow-ups before building a route) currently shares a single bubble slot; Round 2 should define a bounded scrollable message thread (max-height: 28dvh) with stop-preview chips before committing to the map. (c) Social ("Friends") is currently consolidated as a tab inside My Walks to keep navigation to 5 clean items—if friend feeds need commenting or discovery, we should validate whether it warrants its own screen.
