## Ariel's decisions (override plan defaults)
1. **Build everything in the plan's MUST + SHOULD set**, including hygiene fixes (A1–A9), LLM seam (B), memory (C), companion (D), cadence/data (E1, E3), imagery (F1–F3).
2. **Imagery/detected tier is NOT limited to Tel Aviv + Jerusalem.** It covers all of Israel, made safe by **deny-by-default exclusion zones + per-candidate hazard filter + mandatory warnings** (see "Safety model"). It still ships **behind a flag, default OFF in production** (`NEXT_PUBLIC_DETECTED_TIER=1` to enable; Ariel's no-deploy-before-gate rule stands). No deploy/commit/push by builders.
3. **LLM model choice** — see "AI engine decision". Provider is env-selectable; no self-hosted GPU.
4. Dropped from scope (stay DEFER): offline SW, Google provider, shade routing, social, STT, kids mode, PostGIS preload E2 (write the migration + provider seam stub only if cheap; otherwise leave).

## AI engine decision (reasoned)
- Needs: understand free text (HE/EN), extract structured data, short grounded narration, remember prefs. Low volume (~$0.001–0.01/walk). Latency not critical (narration prefetched, in-walk logic deterministic).
- **Self-hosting an open-source model (Llama/Qwen/DictaLM) needs a 24/7 or serverless GPU (~$0.5–1.5/h or cold-start pain) — far costlier and more work than API calls at this volume, and Hebrew quality of small open models is weaker.** So: NO own cloud/GPU now.
- **Open-weight models via hosted inference (Groq/Together/OpenRouter-style OpenAI-compatible endpoint) are supported as an eval candidate** via an `openai-compatible` provider with `LLM_BASE_URL`. This gives "open source" without running servers. Revisit self-hosting only if monthly LLM spend > ~$100 or data-residency demands it.
- **Default (until eval says otherwise): Gemini 3.1 Flash-Lite pinned id, with Cloud Billing enabled (Ariel action A3: stops training on prompts)**; eval runner compares Haiku 5.5, gpt-6-luna/gpt-5-nano, Gemini 3.1 Flash-Lite, and one open-weight hosted model. Winner recorded in CLAUDE.md after Ariel runs the eval with real keys. Builders cannot run the eval live (no keys in agent env) — they build the runner + 70 cases (≥30 Hebrew) + a mock-provider dry run.
- Privacy: never send raw GPS or name; standing facts only if learning consent on; untrusted text in a data block.

## Safety model (applies to detected tier AND to anything suggested off-path)
1. **Deny-by-default zones** (`src/lib/places/safety-zones.ts`, data-driven, unit-tested): coarse conservative polygons/buffers that suppress detected-tier suggestions entirely: Gaza Strip + ~7 km envelope buffer line, Lebanon/Syria/Golan-border strip (~3 km), Jordan Valley/Arava/Egypt border strips (~1.5 km), Judea & Samaria (West Bank, all areas), East Jerusalem Old City surroundings is NOT excluded but flagged "mixed area" warning. Use simplified bounding polygons; mark file header: "coarse, conservative, must be reviewed by Ariel/security-aware human; false positives are OK, false negatives are not". Do not fabricate high-precision coordinates; use rough rectangles/polygons and a TODO list of what to refine. Outside Israel: detected tier off.
2. **Per-candidate hazard filter**: OSM landuse=military / military=*, firing zones, landuse=farmland/orchard/vineyard/greenhouse, private, fenced (barrier=fence/wall near), protected_area/nature_reserve (warn+hours), wadi/stream (flash-flood warn), cliffs, fire-season (Jun–Oct) warn, mined/danger tags → suppress or warn per plan §1.
3. **Reachability rule**: only suggest a detected area if a mapped walkable path/road enters/touches it within 150 m; never suggest "walk across" an unmapped area.
4. Mandatory on every detected card: "Detected from satellite data, not a registered place", at least one warning, "check signs/local rules", no "safe"/"verified" wording, confidence ≤ 0.8, HE+EN.
5. **Never the sole basis for navigation**; ORS/OSM paths only. Day-time bias: suppress detected suggestions when sun below horizon.
6. Emergency: show 100/101/102 hint? (UI footer in detected card only; keep small.)

### H1-H3 (2026-10-12, Sonnet) — routine habits: model, producer, storage

### R3 (2026-10-12, Sonnet) - cost-abuse caps
Goal: nobody, signed in or not, can burn LLM money. Audit then surgical fix.

**What was uncapped (before):** `runLlm` only metered when a `ctx` was passed, and these paths passed none: `resolveCanonicalName` (once per unresolved place name, unbounded by prompt, via `canonicalNameFor`), `extractStandingFacts` (`learnFactsFromText`), `extractCategoryPreferences` (`learnPreferencesFromText`). Both learning passes run from `/api/extract-places` AND `/api/walk-feedback`. `/api/walk-feedback` and `/api/session-summary` also had no rate limit. There was only a per-caller CALL cap and the global $3/day cap; no per-caller dollar cap. `callerKey` trusted `x-forwarded-for` everywhere, so off Vercel an anonymous caller could rotate the header to mint a fresh rate-limit bucket and a fresh anonymous LLM budget per request (IPv6 users could also rotate inside their /64).

**What changed:**
- `runLlm(task, ctx, deps)`: `ctx` is now REQUIRED (type and runtime). The only opt-out is the exported `UNMETERED` symbol (`llm/types.ts`), used by `eval-runner.ts` and the offline tests. All four `gemini-client` wrappers, `learnPreferencesFromText` and `learnFactsFromText` take a required `LlmCallContext` (a test greps `src` for `ctx?: LlmCallContext`). Every call site now builds a ctx from `userId` or the hashed ip.
- Per-caller dollar cap in `budget.ts` (`DAILY_COST_CAPS_MICROS`, enforced in `reserve` from `callerCostMicros`): anonymous $0.05, free $0.25, paid $1.50 per UTC day; override with `LLM_CAP_USD_ANONYMOUS|FREE|PAID`.
- Fan-out: `/api/extract-places` makes at most `MAX_CANONICAL_LOOKUPS_PER_REQUEST = 3` canonical-name calls per request. The tier-3 reorder is one `runLlm` per request by construction (single call site, not in a loop), counted on the same ctx, and `once-per-walk` mode still limits Sol per caller+prompt.
- Rate limit: new `learningRateLimiter` (10/min, 60/day, one shared bucket) on `/api/walk-feedback` and `/api/session-summary`. `callerKey` ignores forwarded headers in production unless `VERCEL` is set or `TRUST_PROXY_HEADERS=1` (everyone then shares the `unidentified` bucket: fails safe for cost); IPv6 addresses collapse to their /64.
- Verified: the guard fails CLOSED in production when `SUPABASE_SERVICE_ROLE_KEY`/URL is missing or the store errors (`LLM_BUDGET_FAIL_OPEN=1` is the only opt-out; tests cover both). LLM failures do not loop: client-side there is no retry, server side `withRetry` is 3 attempts on 429/5xx inside a 10 s budget, then at most one fallback provider; a budget refusal is a 429 that the callers turn into the no-LLM path.
- Tests: `tests/llm-r3-caps.test.ts` (15). Mutants killed: cost-cap check removed, canonical cap 3 -> 4, ctx dropped in `learnPreferencesFromText`, forwarded-header trust gate removed. Existing tests updated for the new signatures only.

**Input/output bounds (checked):** extract-places prompt <= 1000 chars (400 otherwise), learning text sliced to `MAX_LEARNING_TEXT_LENGTH` 1000, walk-feedback comment sliced to 1000, session-summary input is the field-by-field whitelist (`walk-end-whitelist.ts`, walk_end 4k chars), plan candidates trimmed to 8k chars. `maxOutputTokens`: extract-places 512, canonical-name 128, preferences 256, facts 256, session-summary 400, plan 900. Anthropic provider forces `max_tokens >= 1024` (`ANTHROPIC_MIN_MAX_TOKENS`), so on Anthropic the small tasks can bill up to 1024 output tokens, not 128-512: still bounded and still metered by the cost cap. Reasoning tokens on Sol count inside the billed output tokens and are settled the same way.

| Call site | Task (tier, max out) | Caller key | Caps that apply | Calls/request |
|---|---|---|---|---|
| `/api/extract-places` extraction (also follow-up turn) | extract-places (T1, 512) | user id, else hashed ip | rate 10/min 300/day per ip; calls 15/60/300; $0.05/0.25/1.50; global $3 | 1 |

Per reserved call the provider can be hit up to twice (primary, then fallback on timeout/5xx/bad JSON); failed attempts that are retried (429/5xx) are normally not billed, so billed cost per reserved call is at most 2 responses. Max reserved calls per extract-places request: 1 + 3 + 1 + 1 + 1 = 7 (signed in, T3 on), 4 for anonymous (no learning passes).

**Worst-case $ per caller per UTC day** (prices from `pricing.ts`: default T1 gemini-3.1-flash-lite $0.25/$1.5 per M, Sol $2/$10 per M; ~2k input tokens, full max output; figures are estimates, not measured):
- Steady state, enforced by the cost cap: anonymous $0.05, free $0.25, paid $1.50, plus whatever is in flight when the cap trips (settled cost lags the call). One extract-places request is about $0.01 on T1 and about $0.05 with a T3 call.
- Hard burst ceiling if every reserved call were in flight at once before any settles (call cap x worst per-call cost): T1 only anonymous ~$0.02, free ~$0.08, paid ~$0.40; with T3 on and every call a Sol plan call anonymous ~$0.40, free ~$1.50, paid ~$7.50. The ten-per-minute rate limit and the sequential pipeline make that unreachable in practice; the global $3/day cap bounds everyone together regardless.
- Anonymous sybil bound: each new ip gets $0.05, so the real protection against many ips is the global cap and the provider-side limit below.

**Remaining gaps (not built, on purpose):**
1. Rate limiters are in-process (per serverless instance, reset on cold start). On Vercel they are best effort. Recommend Upstash Redis (`@upstash/ratelimit`) keyed by the same `callerKey`. The budget guard (Supabase `llm_usage`) IS shared and atomic, so the money caps hold even when the limiters do not; the limiters only blunt bursts.
2. Set a HARD spend limit in the provider consoles (Google AI Studio / OpenAI / Anthropic monthly budget) as the last line; the app guard is an estimate from list prices and token counts the provider reports.
3. Cost lags the call: concurrent in-flight requests can overshoot a per-caller dollar cap by their own cost (bounded by the call cap above).
4. Anonymous identity is the ip: many ips (botnet, IPv6 across /64s) multiply the anonymous quota; only the global $3 cap and the provider limit stop that. Consider a signed-in-only or CAPTCHA gate for T3 / learning if abuse shows up.
5. Off Vercel with no `TRUST_PROXY_HEADERS`, all production users share one `unidentified` bucket (cap exhausted by one person for everyone): set the env var behind a trusted proxy.
6. Not verified against a live provider or live Supabase RPC (`llm_usage_bump`): the dollar cap is tested with the same fake store the existing budget tests use.
